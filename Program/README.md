# AnyTrack Editor v0.12.8

Локальный редактор тренировок FIT, GPX и TCX. Интерфейс RU / EN.
generated by VJ Ostrov

## Структура архива и запуск

В готовом архиве четыре папки:

- `Program` — общие файлы программы и исходный код;
- `Windows` — `start_windows.bat` и сборка EXE;
- `macOS` — `start_macos.command` и сборка `.app`;
- `Linux` — `start_linux.sh` и сборка исполняемого пакета.

Установите Python 3.11–3.13, затем запустите сценарий своей системы.
При первом старте он создаст отдельное виртуальное окружение и установит
зависимости. Подробности находятся в `README` внутри каждой системной папки.

## Создание маршрута

Нажмите «Создать маршрут», поставьте на карте минимум две контрольные точки,
выберите режим и нажмите «Построить маршрут». Доступны пеший маршрут, бег,
базовый велосипед, шоссейный велосипед, MTB/гравий, «Сплав по реке» и локальный
режим «Напрямик». Готовый маршрут можно сразу сохранить кнопкой «Сохранить
GPX» либо добавить в редактор для дальнейшей правки. Плановый GPX содержит
координаты и доступные значения высоты, но не получает искусственные скорость
и временные метки.

Облачный бесплатный GraphHopper поддерживает базовые профили `foot` и `bike`.
Шоссейный `racingbike` и внедорожный `mtb` рассчитаны на подходящий
платный тариф или локальный сервер. «Напрямик» соединяет контрольные точки
локально, не отправляет запросов и не расходует кредиты.

«Сплав по реке» получает размеченные реки, ручьи и каналы из OpenStreetMap и
ищет связный путь именно по водному графу. Этот специальный режим требует
интернет и не расходует кредиты GraphHopper. Если водные линии в OpenStreetMap
не соединены, приложение не рисует ложный отрезок по суше, а просит уточнить
контрольные точки.

По умолчанию используется облачный адрес `https://graphhopper.com/api/1/route`.
Для него укажите API-ключ в настройках приложения. Там же можно переключиться
на управляемый приложением локальный GraphHopper. При построении во внешний
сервис передаются только контрольные точки нового маршрута, а не открытые
тренировки.

Облачный бесплатный тариф принимает не более пяти мест в одном запросе.
Приложение автоматически делит длинный маршрут на перекрывающиеся части по
пять мест и объединяет ответы без прямых соединительных линий. Поэтому десять
контрольных точек требуют трёх запросов: 1–5, 5–9 и 9–10.

В настройках показаны использованные за день кредиты GraphHopper, дневной
лимит, процент расхода и время до сброса. Надёжное значение обновляется из
служебных заголовков после успешного ответа построителя маршрутов.
Для локального GraphHopper облачный счётчик не применяется.

## Локальный GraphHopper

Откройте «Настройки → Построение маршрутов» и выберите «Локальный
GraphHopper». Дальше достаточно выполнить три действия:

1. Нажать «Установить компоненты» — приложение загрузит GraphHopper 11 и
   переносимую Java 25 в отдельную папку данных.
2. Скачать нужный регион OpenStreetMap по ссылке в настройках и выбрать файл
   `.osm.pbf`.
3. Нажать «Подготовить карту». Первый импорт может занять заметное время и
   дополнительное место на диске; объём зависит от выбранного региона.
   Одновременно GraphHopper загрузит данные высоты SRTM и добавит их в граф.

После подготовки сервер можно запускать вручную или автоматически при нажатии
«Создать маршрут». Он доступен только на `127.0.0.1:8989`, не требует API-ключа
и строит все контрольные точки одним запросом. После первоначальной установки
компонентов и карты интернет для расчёта маршрута не нужен. Фоновые тайлы карты
кешируются отдельно — для полностью автономного отображения заранее используйте
«Скачать карту».

База, подготовленная в версии 0.12.2 или раньше, не содержит рельефа. Чтобы
маршруты локального GraphHopper получили высоту, нажмите «Подготовить карту»
повторно и подтвердите пересборку. Интернет нужен только во время первой
загрузки файлов SRTM; после импорта высота рассчитывается локально.

Компоненты и региональная карта не включены в основной архив программы, поэтому
сама поставка не увеличивается на гигабайты. В настройках всегда видны папка и
текущий размер локального модуля; базу маршрутов можно удалить отдельно.

- Протяните внутри выделения, чтобы переместить его.
- Потяните край, чтобы изменить границу.
- «Вырезать» удаляет отсчёты интервала; «Редактировать» задаёт точные границы;

- Всплывающая подсказка показывает исходные значения, маркеры на кривых —

## Как работает дистанция над графиками

Километры привязаны к записанному продвижению по времени: отметки могут
располагаться неравномерно, если скорость менялась. При остановке расстояние
не растёт. Нельзя получить эту шкалу простым пересчётом общей длительности
в километры по средней скорости.

Для последовательных фрагментов дистанция продолжается накопительно.
Для наложенных записей используется активный трек из этой группы; если у него
нет расстояния, выбирается первый источник с данными. Источники указаны
во всплывающей подсказке верхней оси.

Удалённые интервалы и большие разрывы не добавляют расстояние. При отсутствии
данных шкала не рисуется. Если между фрагментами нет известной длины, следующий
известный фрагмент начинает собственный отсчёт с нуля. Расстояние считается
по доступным данным, поэтому пропуски могут уменьшать его.

## Режимы статистики

| Режим | Основной показатель | Порог движения |
|---|---|---|
| Велосипед | Скорость в движении, км/ч | 0,5 м/с |
| Бег и ходьба | Темп в движении, мин/км | 0,3 м/с |

Режим применяется к общей и выделенной статистике. Он не изменяет спорт
или измерения в исходном файле.

Время движения оценивается по средней скорости соседних сохранённых отсчётов;
при отсутствии скорости используется прирост расстояния / время.
Расстояние берётся из счётчика устройства, при отсутствии корректного
прироста — интегрируется по скорости.

Удалённые интервалы не соединяются при расчёте. Исключаются разрывы больше
пяти обычных шагов записи, с порогом от 30 до 120 секунд.
Скорость = расстояние в движении / время в движении.
Темп = время в движении / расстояние в движении.
При отсутствии данных вместо неопределённого значения показывается «—».

Средние сенсорные значения — арифметическое среднее доступных отсчётов.
Нули мощности и каденса внутри реальной серии учитываются.
Это локальная оценка, а не воспроизведение алгоритма Strava.

Общая статистика суммирует расстояние и время движения всех файлов,
включая наложения; общее время объединяет временные диапазоны.
Верхняя шкала километров использует один опорный источник для наложений,
поэтому её итог может отличаться от суммы в общей статистике.

## Несколько файлов и сохранение

Неперекрывающиеся записи выстраиваются последовательно на общей временной
линии, одновременные остаются наложенными. Флажок трека управляет его
видимостью на карте; графики и статистика учитывают все загруженные файлы.

При нескольких треках «Сохранить файл» предлагает явный выбор:

1. **Активный трек** — сохранить выбранный источник в исходном формате.
2. **Объединённый GPX** — экспортировать сохранённые участки с монтажным временем.
3. **Отдельные файлы** — сохранить каждый источник отдельно.

Кнопка корзины убирает трек из программы, сохраняя исходный файл на диске.
Сглаживание, режим диаграмм и режим спорта не изменяют экспортируемые измерения.

Ограничения форматов:

- FIT: редактируются RECORD; Lap / Session / Activity, таймеры и итоговые
  поля ещё не пересчитываются полностью.
- GPX / TCX: экспортируются поддерживаемые координаты и параметры;
  неизвестные расширения производителя не сохраняются.
- Объединение доступно в GPX. Преобразование GPX → FIT не реализовано.
- «Редактировать» меняет границы выделения, а не значения датчиков.
